# 1Password spike — 2026-11-09

Task 0 of `docs/superpowers/plans/2026-11-09-credential-vault.md`. All values below are dummy
spike values; no real secret was used.

## Desktop-app integration: ruled out

- `op` 2.42.0 (Homebrew cask) with the 1Password app 8.12.44, "Integrate with 1Password CLI" on.
- From any process launched by the Claude desktop app (the Bash tool, its Terminal panel tab, with
  or without the command sandbox): `op whoami` →
  `connecting to desktop app: 1Password CLI couldn't connect to the 1Password desktop app. To fix this, update the 1Password app to the latest version and restart the app.`
- The official Environments MCP server (`/Applications/1Password.app/Contents/MacOS/1password-mcp`)
  lists its tools, but `authenticate` answers `1Password desktop app is not running. Please open 1Password and try again.`
  It manages 1Password Environments, not vault items, and takes secret values as tool arguments.
- From macOS Terminal.app the same `op vault list` works. openai/codex#46405 reports the same split
  for Codex Desktop.
- An AppleScript relay (`do script` in Terminal.app, output to a log file) also works, and was the
  fallback.
- Adding a second account to the app switched the CLI integration off
  (`developers.cliSharedLockState.enabled` disappeared from the app's `settings.json`); `op` then
  fell back to an interactive manual sign-in prompt.

## Service account: chosen

- The first attempt, on a 1Password Business account of a company the founder no longer uses,
  failed with `(402) Unknown: An unknown error occurred.` (payment required).
- On the founder's new personal account (`my.1password.com`), in Terminal.app:
  `{ printf 'add-generic-password -U -a %s -s startup-factory-op -w ' "$USER"; op service-account create startup-factory --can-create-vaults --raw; } | security -i`
  succeeded. The token went straight into the Keychain; it was never displayed.
- From Claude's shell, `security find-generic-password -a <user> -s startup-factory-op -w` reads
  it with no Keychain prompt (819 characters, prefix `ops_`).

With `OP_SERVICE_ACCOUNT_TOKEN` set in the child environment only:

| Probe | Result |
| --- | --- |
| `op vault list` | status 0, no vaults: built-in vaults are invisible to a service account |
| `op vault create startup-vault-spike` | status 0 |
| `op item create --vault <v> -` with the JSON template on stdin | status 0 |
| `op item get <i> --vault <v> --fields F --reveal` | the value |
| `op item get --format json` without `--reveal` | concealed values are included |
| default fields of a `SECURE_NOTE` | `notesPlain` (no value) plus the template fields |
| `op item edit <i> --vault <v>` with the full item JSON piped | status 0; fields replaced and appended |
| `op item edit` with a partial JSON (one field) | status 0, but every other field is deleted: a piped edit **replaces** the item, so always send the full item |
| `op inject -i <file>` with a bare `op://` reference | resolved |
| `op run --env-file=<file> -- printenv A` | `<concealed by 1Password>` |
| `op read op://…` | the value |

The service account can read and write items in a vault it created, so the per-startup vault
layout stands; the single-vault fallback is not needed.

## Error strings (for `FAILURE_PATTERNS`)

- Malformed token: status 9, `failed to DecodeSACredentials: invalid character '\u008a' looking for beginning of value`.
- Missing item: status 1, `"nope" isn't an item in the "startup-vault-spike" vault. Specify the item with its UUID, name, or domain.`
- Missing vault: status 1, `"startup-vault-does-not-exist" isn't a vault in this account. Specify the vault with its ID or name.` (same for `op item get` in a missing vault).
- Missing field in a reference: status 1, `item 'startup-vault-spike/spike' does not have a field 'SPIKE_FIELD'`.
- Documented hourly limit (not provoked): `[ERROR] (429) Too Many Requests: You've reached the maximum number of this type of requests this service account is allowed to make...`.
- A revoked but well-formed token was not tested; expect an HTTP 401 class error.

## Rate limits on this account (`op service-account ratelimit`)

| Type | Action | Limit |
| --- | --- | --- |
| token | write | 100 per hour |
| token | read | 1,000 per hour |
| account | read_write | 1,000 per day |

Request cost per command (docs): `item create` 1 read + 1 write, `item edit` 5 reads + 1 write,
`item get` and `read` 3 reads each. A startup run stays well under these limits if each script
writes its fields in one call, as the plan requires.
