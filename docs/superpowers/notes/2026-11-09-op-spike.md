## Desktop-app integration: ruled out

- `op` 2.42.0 (Homebrew cask) with the 1Password app 8.12.44, "Integrate with 1Password CLI" on.
- From any process launched by the Claude desktop app (the Bash tool, its Terminal panel tab, with
  or without the command sandbox): `op whoami` →
  `connecting to desktop app: 1Password CLI couldn't connect to the 1Password desktop app. To fix this, update the 1Password app to the latest version and restart the app.`
- The official Environments MCP server (`/Applications/1Password.app/Contents/MacOS/1password-mcp`)
  lists its tools, but `authenticate` answers `1Password desktop app is not running. Please open 1Password and try again.`
  It manages 1Password Environments, not vault items, and takes secret values as tool arguments.
- From macOS Terminal.app the same `op vault list` works. openai/codex#46405 reports the same split
  for Codex Desktop.
- An AppleScript relay (`do script` in Terminal.app, output to a log file) also works, and was the
  fallback.
- Adding a second account to the app switched the CLI integration off
  (`developers.cliSharedLockState.enabled` disappeared from the app's `settings.json`); `op` then
  fell back to an interactive manual sign-in prompt.

- Missing item: status 1, `"nope" isn't an item in the "startup-vault-spike" vault. Specify the item with its UUID, name, or domain.`

## Rate limits on this account (`op service-account ratelimit`)

| Type | Action | Limit |
| --- | --- | --- |
| token | write | 100 per hour |
| token | read | 1,000 per hour |
| account | read_write | 1,000 per day |

Request cost per command (docs): `item create` 1 read + 1 write, `item edit` 5 reads + 1 write,
`item get` and `read` 3 reads each. A startup run stays well under these limits if each script
writes its fields in one call, as the plan requires.

## Live run (Task 18, 2026-11-09, founder away)

Run from Claude's shell in an isolated directory (a copy of `.env.template` and a
`startup.config.json` with slug `vault-trial`), against the real service account. Values were
generated trial secrets or dummies.

Two bugs found and fixed:

1. **Node gives `op` a socket, not a pipe (Critical).** `spawnSync(..., { input })` hands the child
   a socketpair on macOS. `op` reads a stdin template only from a named pipe, so
   `op item create … -` failed with `provide the item category with '--category' flag` and
   `op item edit` **exited 0 without applying anything**. Fixed in 692cbe0: `op` runs behind
   `/bin/sh -c 'cat | exec op "$@"'` when input is given, and every `writeFields` re-reads the item
   and fails unless each written field holds its new value.
2. **`op inject` reads comments (Important).** The `.env.template` header mentioned a literal
   `op://startup-<slug>/…`; `.env.prod` inherits it and `op inject -i .env.prod` failed with
   `invalid secret reference 'op://startup-': too few '/'`. Fixed in 799a9ad: the comment no longer
   holds the scheme, and `push-env-to-vercel.mjs` sends only the parsed `KEY=op://…` values to
   `op inject` on stdin. `op run --env-file` ignores comments (checked).

Findings that changed the docs:

- **Google's Copy buttons leak.** Their accessible names contain the value ("Copy to clipboard:
  GOCSPX-…"), so a `find` for them puts the client secret in the transcript. It happened once
  here, on a scratch client that is deleted with its project. The skill now forbids searching for
  them; without "Download JSON" the founder clicks Copy.
- Supabase scoped tokens: resource access "Organization", preset "Full access", expiry "Never".
  `supabase login` is no longer needed.
- PostHog key scopes are now `organization:write` and `project:write`.
- Dash0 has no free plan: a new organization is a 14-day trial.
- Vercel needs the founder's 2FA code on device authorization, and the device code expires within
  minutes. `pnpm add -g vercel` fails when the pnpm global bin is not in `PATH`; the docs now say
  `npm i -g vercel@latest`.
- The founder may use another Google account for a provider that needs a phone number they
  already used (Vercel here).
- Terms of service: the founder agreed, up front, to Claude ticking each provider's terms (Dash0,
  Google Cloud, Google API Services User Data Policy) and the CLI consent pages. Step 0 now asks
  this once.
- Resend was not run: no verified domain (roadmap item 4).
